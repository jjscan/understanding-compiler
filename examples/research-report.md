# 원격 근무와 신입 개발자 온보딩 기간: 사내 조사 보고서

> 테스트 케이스 B — 리서치 보고서. 가상의 회사 데이터를 쓰는 예시 문서다. 수치는 실제 통계가 아니다.

## 요약

원격 근무 팀에 합류한 신입 개발자는 사무실 근무 팀보다 첫 PR 머지까지 더 오래 걸렸다. 다만 멘토 페어링을 운영한 원격 팀에서는 차이가 거의 없었다.

## 1. 조사 방법

2024년 3월부터 2025년 2월까지 입사한 신입 개발자 86명의 저장소 기록을 분석했다. 원격 팀 소속은 47명, 사무실 팀 소속은 39명이다. 첫 PR 머지까지 걸린 영업일 수를 온보딩 기간의 대리 지표로 사용했다.

## 2. 결과

| 집단 | 인원 | 첫 PR 머지까지 중앙값(영업일) |
|---|---|---|
| 사무실 팀 | 39 | 6 |
| 원격 팀(멘토 페어링 없음) | 28 | 11 |
| 원격 팀(멘토 페어링 있음) | 19 | 7 |

원격 팀 전체의 중앙값은 9영업일로 사무실 팀보다 3영업일 길었다.

멘토 페어링 팀의 신입은 첫 달 코드 리뷰 코멘트를 평균 2.4배 더 많이 받았다(리뷰 시스템 로그 기준).

## 3. 해석

멘토 페어링이 원격 근무의 온보딩 지연을 해소한다. 리뷰 코멘트가 많을수록 신입이 코드베이스의 관습을 빨리 익히기 때문으로 보인다.

외부 연구도 비슷한 경향을 보고한다. GitLab의 2023 원격 근무 보고서는 원격 신입의 생산성 도달 시간이 더 길다고 밝혔다.

## 4. 한계

표본이 86명으로 작고, 팀 배정이 무작위가 아니다. 멘토 페어링은 희망한 팀만 운영했으므로, 원래 온보딩에 관심이 많은 팀이었을 가능성이 있다.

첫 PR 머지 시점은 팀마다 PR 크기 기준이 달라 직접 비교하기 어렵다.

## 5. 권고

모든 원격 팀에 멘토 페어링을 의무화해야 한다. 이렇게 하면 온보딩 기간이 사무실 팀 수준으로 줄어들 것이다.
